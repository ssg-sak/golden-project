# 기업 관계자 방문 대비 개인 프로젝트 로드맵

작성일: 2026-07-27

방문일: 2026-08-22(토)

준비 기간: D-26 ~ D-Day

대상 프로젝트: 대구 골든타임 · Golden Governance

## 1. 문제 분석

이번 준비의 목표는 새 기능을 많이 추가하는 것이 아니라, 기업 관계자가 짧은 시간 안에 다음 내용을 신뢰할 수 있게 보여주는 것이다.

1. 어떤 문제를 왜 선택했는가
2. 본인이 어디까지 설계하고 구현했는가
3. 데이터와 분석 결과를 어떻게 검증했는가
4. 서비스가 실패하거나 데이터가 오래됐을 때 어떻게 안전하게 동작하는가
5. 이 경험이 기업의 실제 데이터·서비스 업무에 어떻게 연결되는가

### 현재 확보된 기준선

| 항목 | 2026-07-27 현재 확인 내용 | 활용 방법 |
|---|---|---|
| 공개 서비스 | GitHub Pages 공개 주소와 2026-07-24 브라우저 검증 기록 존재 | 현장 기본 데모 |
| 프로젝트 포트폴리오 | 12쪽 PDF 정본 존재 | 관계자 사전·사후 전달 |
| 전달 패키지 | 소스·보고서·이미지를 포함한 ZIP 존재 | 오프라인 백업과 증거 묶음 |
| 자동 검증 | 2026-07-26 보고서에 단위·통합·E2E·데이터·보안 검증 기록 | 기술 신뢰성 설명 |
| 재현성 | PDF와 실행형 EDA의 반복 SHA-256 일치 기록 | 분석 재현성 설명 |
| 한계 문서화 | ETA, 병상 조회값, 후보 9곳 내부 비교 등 한계가 명시됨 | 과장 없는 답변 |

### 방문 전 닫아야 할 위험

1. 2026-07-26 최종 테스트 보고서는 공개 배포본 재검증과 공공망 성능 측정 2건이 미실행이어서 `조건부 통과`다.
2. 현재 브랜치는 `agent/readme-portfolio-summary`이며, GitHub Pages는 `main` 반영 후에만 최신 상태를 보여준다.
3. 현재 작업 트리에 `data/hospitals.db`, `golden-data-lab/`, `test_api.json` 변경이 섞여 있어 방문용 기준본을 먼저 분리·고정해야 한다.
4. 좋은 기술 문서는 이미 많지만, 기업 관계자 관점의 짧은 설명과 개인 기여도 전달은 별도 연습이 필요하다.
5. 인터넷·외부 API·배포 서비스 장애가 발생해도 설명을 계속할 수 있는 오프라인 동선이 필요하다.

## 2. 해결 방법과 완료 기준

### D-Day 목표

관계자가 프로젝트를 본 뒤 다음 세 문장을 자연스럽게 말할 수 있게 만든다.

- 공공데이터를 모아 화면만 만든 것이 아니라, 데이터 품질과 재현성까지 관리한 프로젝트다.
- 시민용 탐색 서비스와 정책용 공간 분석을 하나의 제품 흐름으로 연결했다.
- 개인 프로젝트지만 운영 실패, 보안, 한계와 향후 검증 계획까지 기업 수준으로 설명할 수 있다.

### 최종 완료 기준

- [ ] 30초 소개, 3분 요약, 8분 기본 데모, 15분 기술 설명을 준비한다.
- [ ] 새 브라우저에서 기본 8분 동선을 연속 3회 성공한다.
- [ ] 낯선 PC 또는 별도 사용자 프로필에서 데모를 1회 이상 성공한다.
- [ ] 프론트·백엔드·분석·빌드·보안 검증을 최종 기준 커밋에서 다시 통과한다.
- [ ] 공개 배포본과 최종 기준 커밋이 일치하며, 공개 브라우저 재검증을 완료한다.
- [ ] 공공망 또는 실제 모바일 환경의 성능을 측정하고 결과의 범위를 기록한다.
- [ ] PDF·ZIP·스크린샷·핵심 문서·오프라인 화면을 한 폴더에서 열 수 있게 준비한다.
- [ ] 주요 예상 질문마다 근거 문서 또는 정직한 한계 답변을 연결한다.
- [ ] 8월 19일부터 신규 기능을 중단하고 결함 수정·리허설만 수행한다.
