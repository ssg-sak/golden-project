# 대구 골든타임

대구광역시의 응급의료기관 탐색과 행정동별 의료 접근성 분석을 연결한 공공데이터 기반 웹서비스입니다. 시민에게는 현재 위치에서 확인할 응급의료기관 정보를 제공하고, 행정·정책 관점에서는 실제 도로 이동시간과 보호가 필요한 인구를 함께 고려해 취약지역과 거점 후보를 비교합니다.

[서비스 바로가기](https://ssg-sak.github.io/golden-project/) · [정책분석 보고서](frontend/public/data/reports/golden-governance-portfolio.pdf) · [공개 데모 검증 보고서](docs/reports/DEMO_VALIDATION_REPORT_20260724.md)

> 병상·진료·수용 정보는 조회 시점의 참고값입니다. 응급상황에서는 119·1339 또는 의료기관에 직접 확인해야 합니다.

## 1. 프로젝트 소개

### 한 문장 소개

시민용 응급의료기관 탐색과 정책용 의료 접근성 분석을 하나의 데이터 흐름으로 연결한 서비스입니다.

### 사용자

- 시민: 현재 위치에서 가까운 응급의료기관, 예상 이동시간, 전화·길찾기, 조회 가능한 운영정보 확인
- 행정·정책 검토자: 행정동별 취약지역, 보호가 필요한 인구, 도로 기반 접근성, 신규 거점 후보 비교

### 핵심 관점

가까운 기관을 나열하는 데서 끝내지 않고, 실제 도로 이동시간과 대상 인구를 함께 살펴보며 “어디가 더 취약한가”와 “어떤 후보 조합을 우선 검토할 것인가”를 분리해 보여줍니다.

## 2. 문제 정의

응급의료 접근성을 직선거리나 병원 목록만으로 판단하면 강·철도·간선도로 우회, 생활권 단절, 대상 인구 분포를 충분히 반영하기 어렵습니다. 시민 화면 역시 병원명만 제공하면 중증질환 수용 가능 여부나 정보의 최신성을 판단하기 어렵습니다.

이 프로젝트는 다음 문제를 해결하는 것을 목표로 합니다.

1. 시민이 출발 전에 확인해야 할 응급의료기관 정보를 한 화면에서 확인한다.
2. 행정동별 보호가 필요한 인구와 실제 차량 이동시간을 결합해 상대적인 접근성 취약성을 비교한다.
3. 신규 거점 후보를 확정안이 아닌 비교 가능한 정책 검토 자료로 제시한다.
4. 외부 API 장애와 데이터 최신성 한계를 화면과 문서에서 숨기지 않는다.

## 3. 데이터

### 분석 범위

| 항목 | 현재 검증본 |
|---|---:|
| 분석 지역 | 대구광역시 |
| 행정동 | 150개 |
| 기준 응급의료기관 | 25개 |
| 안정 후보지 | 9곳 |
| 도로 경로 | 5,100건 성공, 누락 0건 |
| 후보 민감도 분석 | 소아 240회, 어르신 240회 |

### 주요 데이터와 용도

| 데이터 | 용도 | 상태 |
|---|---|---|
| 행정동 경계·중심점 | 분석 단위와 출발점 정의 | 정책 분석 입력 |
| 인구 자료 | 소아·고령층 등 보호가 필요한 인구 산출 | 기준월이 기록된 분석본 |
| 응급의료기관 자료 | 기준 기관과 시민용 기관 정보 구성 | 공공 원천·정제본 |
| 도로 이동시간 | 행정동에서 기관·후보까지의 차량 ETA 비교 | 저장된 분석 결과 |
| 정책 릴리스 JSON | 분석 결과의 단일 정본과 해시 관리 | `data/processed/policy_release.json` |

데이터 계보, 컬럼 의미, 단위, JOIN 규칙, 결측값 해석은 [데이터 사전](docs/core/data_dictionary.md)에 정리했습니다. 원천의 최신성 검증과 품질 이슈는 [데이터 품질 보고서](docs/reports/DATA_QUALITY_REPORT.md)를 참고하세요.

## 6. 분석 과정

```mermaid
flowchart LR
    A[공공데이터 수집] --> B[정제·좌표·키 품질검사]
    B --> C[보호가 필요한 인구와 VDI 산출]
    C --> D[K-Means 후보 민감도 분석]
    D --> E[도로 ETA 5,100건 구축]
    E --> F[p-median·MCLP 후보 조합 비교]
    F --> G[정책 릴리스 JSON·PDF 생성]
    G --> H[FastAPI·React 제공]
```

핵심 분석은 다음 원칙을 따릅니다.

- VDI는 `ln(1 + 일반 차량 ETA 분)`과 보호가 필요한 인구를 결합한 프로젝트 내부 상대 비교 지표입니다.
- 후보 분석은 안정 후보 9곳 안에서 1~3개 거점 조합을 비교합니다.
- 도로 ETA는 일반 차량 기준이며 119 구급차 운행시간이나 임상적 위험을 의미하지 않습니다.
- 데이터 계약과 해시 검사를 통과한 결과만 정책 릴리스로 승격합니다.

자세한 산식과 해석 경계는 [접근성 분석 방법론](docs/core/methodology.md)에 기록했습니다.

## 7. 주요 결과

현재 검증본에서 확인된 대표 결과는 다음과 같습니다.

**비교 기준:** Release `2026-07-r1` / Population `2026.07` / 모드별 기존 기준 기관 유지 + p-median 3개 후보 / 대상 인구 가중 일반 차량 도로 ETA

| 결과 | 검증 내용 |
|---|---|
| 후보 안정성 | 소아·어르신 각각 240개 조건을 분석해 후보 민감도를 확인 |
| 도로 접근성 | 150개 행정동과 34개 기관·후보 조합, 총 5,100건 경로 성공 |
| 평균 ETA | 소아 16.237분→13.286분, 어르신 12.034분→11.269분 |
| 15분 도착 비율 | 기존 기관을 포함한 전체 체계 기준 소아 41.44%→64.01%, 어르신 79.19%→84.00% |
| 검증 상태 | 분석·백엔드·프론트엔드·E2E 검증 기록과 데이터 계약을 문서화 |

후보 조합과 후보 적용 후 ETA는 [`policy_release.json`](data/processed/policy_release.json), 기준선과 전체 체계의 시간대별 도착 비율은 동일 해시의 [도로 ETA 행렬](frontend/public/data/actual_road_accessibility_matrix.json)을 [`kpi_metrics.py`](scripts/kpi_metrics.py)로 재산출해 추적할 수 있습니다.

이 수치는 후보지 확정, 실제 환자 이송 성과, 대구 전역의 절대적 최적해를 의미하지 않습니다. 정책 판단 전 현장 조사·예산·부지·의료자원 검토가 필요합니다.

## 8. 실행 방법

### 요구 환경

- Node.js 22.22 이상
- Python 3.11
- 지도·외부 공공데이터 연동 시 환경 변수 설정

### 프론트엔드

```bash
npm ci --prefix frontend
npm run dev
```

### 백엔드

```bash
cd backend
python -m venv .venv

# Windows
.venv\Scripts\activate

# macOS/Linux
# source .venv/bin/activate

pip install -r requirements.txt
uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

### 정책 분석 파이프라인

```bash
pip install -r requirements-analysis.txt
python ai-model/run_integrated_policy_pipeline.py
```

저장된 도로 결과를 재사용하는 오프라인 실행은 다음과 같습니다.

```bash
python ai-model/run_integrated_policy_pipeline.py --offline
```

환경 변수 예시는 [`.env.example`](.env.example)에 있습니다. 비밀키는 커밋하지 않아야 합니다.

## 10. 한계 및 개선점

### 현재 한계

- ETA는 단일 수집 시점의 일반 차량 기준이며 119 이송시간이 아닙니다.
- VDI는 상대 비교용 분석 지표이며 의료적 위험함수·법정 기준·임상 예측모델이 아닙니다.
- 병상·의료진·실제 환자 흐름·구급차 우선통행·부지·예산·법적 조건은 후보 모델에 포함되지 않았습니다.
- 외부 API 장애나 갱신 지연이 있을 수 있으며, 시민 화면의 운영정보와 정적 정책 분석본은 서로 다른 데이터 수명주기를 가집니다.
- 후보 조합 결과는 안정 후보군 내부 비교이며 대구 전체의 확정 최적 입지를 의미하지 않습니다.

### 개선 방향

1. 데이터 수집 시각과 원천 상태를 화면에 더 명확히 표시하고 운영 로그 기반 최신성 KPI를 축적합니다.
2. 교통 상황·시간대·요일별 ETA를 추가해 단일 시점 비교의 한계를 줄입니다.
3. 부지 비용, 의료 인력·장비, 재난·구급차 운영 조건을 포함한 다기준 후보 평가로 확장합니다.
4. 실제 사용자 동선과 접근성 피드백을 수집해 시민 화면의 이해도와 오류 대응을 개선합니다.
5. 지속적인 운영 데이터와 동시 편집·감사 로그가 요구될 때만 영속 데이터베이스와 인증 구조를 단계적으로 검토합니다.
